# Security

Use HTTPS and a restrictive Content Security Policy. Self-host model and WASM assets when supply-chain controls require it, pin dependency versions, and verify asset integrity in the deployment pipeline.

If embeddings leave the browser, encrypt transport and storage, isolate encryption keys, enforce least-privilege access, audit access without logging biometric content, and implement tested deletion. Keep retention short and document backups. Never place vectors in URLs, telemetry, exception messages, or client-side logs.

Similarity is vulnerable to replay and presentation attacks. Version 0.1.0 does not perform liveness (`performed: false`, `status: not_checked`) and must not be described as bank-grade anti-spoofing or legal identity verification. Pair it with risk-appropriate liveness, rate limits, device/session controls, and human review where required.

Thresholds are model- and population-specific. Validate false-match and false-non-match rates on representative data. Monitor demographic performance and applicable biometric/privacy law with qualified counsel.

Report suspected vulnerabilities privately to the repository owner rather than opening an issue containing biometric data.
